What should happen: Both tests should fail. AES-GCM recomputes the authentication tag when decrypting. With the wrong key or changed data, the tag does not match, so the browser refuses to decrypt. (It cannot tell which of the two happened.) We are not breaking AES here; we are showing how it responds.

Step 5: Compare it with Caesar cipher
Caesar cipher is a lot easier to break because there are only 26 possible shifts. The attack tries all of them and uses English letter frequency to pick the right one, without knowing the key.

The difference: We can try every Caesar shift and find the original message. AES-256 has 2^256 possible keys, far too many to try, and AES-GCM also checks for tampering.

Step 6: The IV-reuse attack
AES-GCM is only safe if every message gets a new IV. Here we break that rule on purpose and recover a secret message without the key.

What the attacker recovered (CA ⊕ CB ⊕ Message A, no key used)

    

    
Why it works: GCM makes a keystream from the key and IV, then XORs it with the message. Same key + same IV means the same keystream, so CA ⊕ CB = A ⊕ B. If the attacker knows A, they get B. Reusing an IV also lets an attacker forge the authentication tag. CipherSafe avoids all of this by picking a random 12-byte IV for every message.
